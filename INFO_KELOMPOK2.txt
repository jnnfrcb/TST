4. STRUKTUR TABEL DAN RELASI

- users: tabel utama pengguna dengan role admin dan user.
- profiles: berelasi dengan users melalui user_id.
- mata_kuliah: berelasi dengan users melalui user_id.
- kategori: berelasi dengan users melalui user_id.
- tugas: berelasi dengan users, mata_kuliah, dan kategori.
- pengumpulan: berelasi dengan users dan tugas.

5. DAFTAR ENDPOINT API

Keterangan hak akses:
PUBLIK = tanpa login.
USER + ADMIN = membutuhkan token JWT dan dapat digunakan oleh kedua role.
ADMIN = hanya dapat digunakan oleh admin.

A. ENDPOINT PUBLIK
GET    /api/ping       - Mengecek API.
POST   /api/register   - Registrasi akun user.
POST   /api/login      - Login dan mendapatkan token.

B. ENDPOINT AUTENTIKASI
GET    /api/me         - Melihat informasi akun yang sedang login.
POST   /api/logout     - Logout dan melakukan blacklist token.

C. ENDPOINT MATA KULIAH
GET     /api/mata-kuliah
GET     /api/mata-kuliah/{id}
POST    /api/mata-kuliah
PUT     /api/mata-kuliah/{id}
PATCH   /api/mata-kuliah/{id}
DELETE  /api/mata-kuliah/{id} (ADMIN)

D. ENDPOINT KATEGORI
GET     /api/kategori
GET     /api/kategori/{id}
POST    /api/kategori
PUT     /api/kategori/{id}
PATCH   /api/kategori/{id}
DELETE  /api/kategori/{id} (ADMIN)

E. ENDPOINT TUGAS
GET     /api/tugas
GET     /api/tugas/{id}
POST    /api/tugas
PUT     /api/tugas/{id}
PATCH   /api/tugas/{id}
DELETE  /api/tugas/{id} (ADMIN)

F. ENDPOINT PENGUMPULAN
GET     /api/pengumpulan
GET     /api/pengumpulan/{id}
POST    /api/pengumpulan
PUT     /api/pengumpulan/{id}
PATCH   /api/pengumpulan/{id}
DELETE  /api/pengumpulan/{id} (ADMIN)

G. ENDPOINT PROFILE
GET     /api/profile
GET     /api/profile/{id}
POST    /api/profile
PUT     /api/profile/{id}
PATCH   /api/profile/{id}
DELETE  /api/profile/{id} (ADMIN)

Hak akses endpoint C-G:
- GET, POST, PUT, PATCH: USER + ADMIN.
- DELETE: ADMIN saja.
- User hanya dapat melihat dan mengubah data miliknya sendiri berdasarkan user_id.
- Admin dapat mengelola seluruh data.

Catatan:
- Pada request role user, user_id ditentukan otomatis berdasarkan token login melalui middleware.
- Pada request role admin, user_id digunakan untuk menentukan pemilik data jika didukung oleh controller.
- Sesuaikan ID relasi dengan data yang tersedia di database.

7. DAFTAR RESPONSE KESALAHAN

401 Unauthorized:
Token tidak tersedia atau tidak valid.

403 Forbidden:
Role tidak memiliki izin, misalnya user mencoba menghapus data.

404 Not Found:
Data tidak ditemukan atau data bukan milik user yang sedang login.

422 Unprocessable Entity:
Data request tidak memenuhi validasi.

8. POSTMAN COLLECTION

Lokasi file:
TaskMate/postman/KELOMPOK2.postman_collection.json

Petunjuk:
- Jalankan request Login USER untuk mendapatkan token user.
- Jalankan request Login ADMIN untuk mendapatkan token admin.
- Token disimpan pada variabel collection.
- Gunakan token sesuai role untuk menguji hak akses.
